# AGENTS.md — agentic-feature-factory

Contributor rules for this repository, for humans and coding agents alike. (`CLAUDE.md`
imports this file.)

## What this repo is

A plugin made of **prompts**, not an application: `commands/*.md` (slash commands),
`agents/*.md` (subagents) and `skills/*/SKILL.md` (build gates). They are the single source of
truth. `scripts/adapt.mjs` is a zero-dependency Node CLI that generates each platform's copy
from them (Antigravity/AGY, Codex, Copilot) and registers the plugin for Claude Code.

## Language

Everything is in **English**: prompts, README, CHANGELOG, code comments and **commit
messages**. Commits follow Conventional Commits (`feat:`, `fix:`, `docs:`, `chore:`, …).

## Writing prompts

- Commands talk to the agent as **"you"** and refer to the user as **"me"**; agents are
  sub-agents that cannot talk to the user, so they report instead of asking.
- Keep the shared vocabulary: *feature*, *work package (WP)*, *wave*, *gate*, *graft*,
  *planning layout*.
- Platform-specific instructions (Claude Code / Antigravity / Codex / Copilot) live side by
  side in the same prompt — never fork a command per platform.
- Some text is shared by several commands and must stay identical in meaning. When you change
  one of these, grep every command and agent:
  - planning layout resolution (settings file → discovery → default `content/`);
  - the settings file search order (`.agentic-feature-factory.local.md` in the repo root, then
    `.agents/`, `.codex/`, `.claude/`);
  - the feature status lifecycle: `specified → planned → in-progress → implemented →
    reviewed → done`;
  - the `git.*` and `models.*` defaults.

## Adding or renaming a command

1. `commands/<name>.md` with frontmatter `description` (and `argument-hint` if it takes
   arguments). The adapter reads both from there: do not duplicate them elsewhere.
2. Add `<name>` to `COMMAND_NAMES` in `scripts/adapt.mjs`.
3. Mention it in the pipeline texts generated by the adapter (Antigravity rules and Copilot
   instructions in `scripts/adapt.mjs`).
4. README: the *What's inside* table, the Antigravity and Copilot command lists and, if it is a
   pipeline step, the quick start and the flow diagram.
5. A `CHANGELOG.md` entry under `[Unreleased]`.

`npm test` fails if steps 2–4 are missed.

## Adding an agent

Add it to `AGENTS` in `scripts/adapt.mjs` with its `modelRole` (`implementer` or `reviewer`),
and give every command that dispatches it the per-platform dispatch block (Agent tool /
`invoke_subagent` / `spawn_agent` / Copilot sub-session) with the resolved model.

## Releasing

- Bump the version in **both** `package.json` and `.claude-plugin/plugin.json`
  (SemVer: a new command, agent or setting key is *minor*; a prompt fix is *patch*).
- Move the `[Unreleased]` entries of `CHANGELOG.md` under the new version, with the date.
- New setting keys must stay optional, with documented defaults.

`npm test` checks that the two versions match and that the CHANGELOG has the current one.

## Verifying a change

```bash
npm test                                   # node:test suite, never touches your real home
node scripts/adapt.mjs all --dry-run       # preview what each adapter would write
```

To try your edits in Claude Code: `npm run adapt claude` (registers this clone as a
`directory` marketplace), then `/plugin marketplace update agentic-feature-factory` and
restart the session.

## Git

Never commit on `main`: work on a `feature/<slug>` branch and open a PR.
